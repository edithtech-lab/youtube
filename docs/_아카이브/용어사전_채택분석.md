# 단면·문화유산 시각화 용어 사전 — 채택 분석

2026-08-12. 용어 약 120개를 우리 스키마와 대조.

---

## 0. 결론 먼저

**용어를 늘리는 게 아니라 축(axis)을 나눠야 한다.** 문서 §14가 정확히 그 얘기를 하고 있고, 이게 이 문서에서 가장 값어치 있는 부분이다. 나머지 120개 용어의 대부분은 §14의 축 안에 들어가는 값이거나, 우리에겐 쓸 수 없는 것이다.

---

## 1. 우리 스키마의 구조적 문제 (근거)

지금 `style` 하나가 **서로 다른 축 3개를 뭉쳐** 들고 있다.

| 우리 톤 | 실제로는 |
|---|---|
| `docu3d` | 렌더=포토리얼 + 투영=원근 + 리빌=없음 |
| `xsection` | 렌더=포토리얼 + 투영=원근 + **리빌=전체단면** |
| `blueprint` | **렌더=선화** + **투영=정사** + 리빌=없음 |

그래서 "클레이 렌더 + 부분절개"를 원하면 **톤을 새로 만들어야 한다.** 조합마다 톤이 하나씩 필요해지는 구조 — 이게 조합 폭발이다.

`shot` 필드도 같은 오류가 있다 (`main.py:2370`):
```
macro | cutaway | wide | close | pov | object | screen
```
`macro·wide·close`는 **화각**, `object·screen`은 **피사체 배치**, `cutaway`는 **리빌 방식**이다. 셋이 한 필드에 섞여 있어서 "와이드로 잡은 부분절개"를 표현할 방법이 없다.

→ **`cutaway`를 `shot`에서 빼내 별도 축으로 올리는 것이 옳다.**

## 2. 축을 다 나눠야 하나 — 아니다

문서 §14는 축 6개를 제안한다. 전부 넣으면 분해기·UI·저장·프롬프트 4곳 × 6필드를 맞춰야 하고, LLM이 모순 조합(blueprint + photoreal)을 뱉을 자유도가 커진다.

**우리 상황에 맞는 최소 구성은 신규 1개 + 확장 2개다.**

| 문서의 축 | 우리 대응 | 판단 |
|---|---|---|
| `render_style` | ≈ `style` 14종 | 확장 (클레이·화이트모델 2종 추가) |
| **`reveal_method`** | **없음** (`shot: cutaway` 하나뿐) | ⭐ **신규 필드** |
| `analysis_layer` | ≈ `anno_kind` (arrow/flow/hud/glow/zone/reject) | 확장 (void·route 2종 추가) |
| `projection_type` | 없음 | 보류 — 아래 3-C |
| `section_orientation` | 없음 | `reveal_method` 값에 흡수 |
| `heritage_evidence_status` | 없음 (홀로그램이 일부 대신) | ⭐ 검토 가치 큼 |

신규 필드 1개(`reveal` 6값)가 톤 14종과 곱해져 **84가지 조합**을 연다. 톤을 6개 더 만드는 것보다 압도적으로 싸다.

## 3. 항목별 채택 판정

### A. 즉시 값어치 있는 것 (우리 콘텐츠에 직결)

| 용어 | 왜 우리에게 중요한가 | 우리 현황 |
|---|---|---|
| **Partial Cutaway / Breakout Section** | 외형 실루엣을 남긴 채 내부를 연다. 피라미드·트로이 목마처럼 **외형 자체가 상징인 대상**에 필수. 통째로 자르면 "이게 뭐였지"를 잃는다 | ❌ `SHOT_LINES["cutaway"]`가 "sliced open"(통째로 자름)만 지시 |
| **Void Mapping** | 피라미드 편의 주제가 문자 그대로 "Five Voids"다. 방·통로·빈 공간을 강조하는 도구 | ❌ `ANNOTATION_GLOW`는 *"clings exactly to that thing's surface"* — **표면이 있는 물체 전용**. 빈 공간엔 못 쓴다 |
| **Ghosted View** | 실물 유지 + 내부 반투명. X-ray보다 안전(껍질을 녹이지 않음) | △ 홀로그램②가 유사하나 시안 와이어프레임 한정 |
| **Confidence Coding / Uncertainty Visualization** | "확실한 것 / 추정 / 가설"을 시각적으로 구분. 역사 콘텐츠의 **신뢰도 장치**이자, GPT §23의 "모르는 구조를 지어내지 마라"에 대한 답 | ❌ 없음 |
| **Circulation / Processional Route** | "왕의 시신이 이 통로로 들어갔다" — 공간 + 서사를 한 번에 | △ `flow`로 대체 가능하나 의미가 물리 흐름 쪽 |
| **Load-Path / Force-Flow** | 하중 전달 경로 | ✅ 2026-08-12 `flow`로 확보 |
| **Poché / Section Hatch** | 잘린 면을 단색·해칭으로 채워 단면임을 명확히 | ❌ 없음 (클레이 단면과 세트) |

### B. 조합·레시피로 이미 되는 것 (코드 수정 불필요)

| 용어 | 우리 조합 |
|---|---|
| Sectional Perspective | `xsection` + `shot: wide` |
| Longitudinal / Transverse Section | `subject_en`에 절단 방향 명시 |
| Structural Skeleton | `subject_en` + `tech3d` |
| Scale Figure / Comparison Silhouette | 홀로그램 ④ 스케일 비교 |
| Archaeological / Virtual Reconstruction | 홀로그램 ① 과거 재구성 |
| Ghost Reconstruction / Ruin-to-Original Overlay | 홀로그램 ① 그 자체 |
| Airflow / Water-Flow / Thermal Flow | `anno_kind: flow` |
| Before-and-After | 체인 2컷 |
| Construction Phasing / Layer-by-Layer | 체인 3컷 (한 클립 다단계는 금지) |
| Detail Inset / Magnified Detail | 별도 컷으로 분리 (720p 인셋은 뭉개짐) |

### C. 보류 — 근거 있는 판단

| 용어 | 보류 이유 |
|---|---|
| **Axonometric / Isometric / Dollhouse View** | 이미지 모델은 평행투영을 잘 못 그린다 — 지시해도 원근으로 돌아간다. 다만 "isometric illustration"은 플랫 일러스트 계열에선 잘 나오므로 **`illust` 톤 한정으로 테스트 후 판단** |
| **Point Cloud** | 수천 개 미세 점 = 우리가 문서화한 720p 붕괴 패턴 그 자체 |
| **Photogrammetry · LiDAR · SfM · Scan-to-BIM · HBIM · Digital Twin** | **측량·기록 방법론이지 화풍이 아니다.** 프롬프트로 지시할 대상이 아님 |
| **Measured Survey · As-Built** | 위와 같음 |
| Sightline / Viewshed Analysis | `zone`+`flow` 조합으로 근사 가능. 전용 도구는 과함 |
| 4D Construction Simulation | Construction Phasing과 사실상 동일 |

### D. 프롬프트에 넣으면 오히려 해로운 것

문서에는 CAD 소프트웨어 기능명이 다수 섞여 있다:
`Live Section` · `Section Box` · `Clipping Plane` · `3D Section` · `Cross-Section` · `Vertical Section`

**이미지 모델 입장에서 이것들은 전부 "잘라서 속을 보여줘"라는 같은 말이다.** CAD에서는 조작 방식이 다르지만 결과 이미지는 구분되지 않는다. 유사어를 여러 개 넣으면 우리가 문서로 남긴 실패 — *"프롬프트끼리 싸우면 반쪽 결과가 나온다"* — 를 부른다.

→ **리빌 방식은 6~8개로 추린 폐쇄 목록으로 관리한다.**

## 4. 권장 신규 필드안

```
reveal (리빌 방식) — 기본값 "" (안 자름)
  full_section      전체 관통 절단          ← 지금의 shot:cutaway
  partial_cutaway   외형 유지 + 일부만 개방   ← 신규·최우선
  breakout          관심 영역만 국부 파냄     ← 신규
  ghosted           실물 유지 + 내부 반투명   ← 신규
  layer_reveal      겉→속 한 겹씩 (체인 전용)
  exploded          분해뷰                  ← 이미 있음(키워드 판별)
```

`anno_kind` 확장 2종:
```
  void   빈 공간·방·통로를 부피로 강조   ← Void Mapping
  route  사람·물건이 이동한 동선          ← Circulation
```

`evidence` (문화유산 컷 한정, 기본값 "" ):
```
  solid        현존 유구 — 완전 불투명·실사
  inferred     근거 있는 추정 — 살짝 깨끗한 재질
  hypothetical 가설 — 절제된 와이어프레임만
```
