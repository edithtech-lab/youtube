### 교정 (3건)

**F5 — 인과가 코드 근거를 못 갖는다. ★ 딱지 회수 권고.**

```python
main.py:1984  ANNO_KINDS      = {"hud", "measure", ...}      # hud 도 정식 멤버
main.py:1988  ANNO_ALIAS      = {"hud": "measure"}
main.py:1991  ANNO_SPAN_KINDS = {"hud", "measure", "arrow", "flow", "route"}
```

`_finish_split:6165` 의 `if c["anno_kind"] not in ANNO_SPAN_KINDS` 검사에 **`hud` 가 이미 들어 있다.**
즉 모델이 `hud` 를 쓰든 `measure` 를 쓰든 **코드는 완전히 동일하게 동작한다** — 끝점 보존,
별칭 변환, 치수선 렌더까지. F5 가 인용한 실측 사고(대회랑 43m)는 **끝점 부재**가 원인이지
**이름 분열**이 원인이 아니다. 둘을 인과로 이으면 안 된다.

남는 위험은 순수 독해 문제 하나뿐이다: "enum 을 보고 `measure` 를 고른 모델이 [4-e]의
`hud·arrow·flow·route` 목록에서 자기를 못 찾는 경우". 그런데 **[4-d] L3061-3062 에 다리가 이미 있다**
— *"measure — 치수·수치·계측. measure_en 이 있고 끝점([4-e])을 줄 수 있으면 이것. (옛 이름 hud 도
그대로 받는다 — 같은 도구다)"*. 두 문장이 각각 [4-e] 참조와 동일성 선언을 한다.

→ **B-1 은 하되 "정리"이지 "사고 방지"가 아니다.** 우선순위를 B-5 와 같은 급으로 내려라.

**F9 — 범위 과대. 영상은 T2V 경로 한정.**
`main.py:6963` 의 `scene_ko` 폴백은 **이미지가 없을 때(T2V)만** 탄다. I2V(정상 경로)는
`MOTION_PROMPT_I2V` 로 빠져(6956) `scene` 변수 자체를 안 만든다. 이미지 쪽(6409)은 무조건 탄다.
→ 문서에 "영상 프롬프트"라고 쓰면 과장이다. **"이미지 프롬프트 + T2V 영상"** 으로 좁혀라.

**F12 — 위험도 과대. 자동 적용 경로가 없다.**
`MOTION_PRESETS` 의 유일한 사용처는 `main.py:6714` 로, **영상 탭 셀렉트 목록을 만드는 것**뿐이다.
`MOTION_PRESET_MAP`(1168)은 **정의만 되고 어디서도 쓰이지 않는다**(전수 grep 확인).
분해기가 이 프리셋을 자동으로 물리는 경로는 없다 — 사용자가 UI 에서 직접 골라야만 들어간다.
→ F12 는 사실이지만 **A-2 의 우선순위를 최하로 내리는 근거**다.

## 2. 버킷 A 판정

### A-1 — 채택. 3차가 제시한 반증 경로 3개를 전부 확인했고, 전부 막혔다

**(a) 프론트가 다른 경로로 컷을 보내는가 → 아니다.**
`generate_images` 호출자는 `ui/index.html:2762`(`icStart` 내부) 하나뿐이고,
`icStart` 진입점 6곳이 **전부** `icPayload` 를 통과한다:

```
2779  icStart(cuts.map(icPayload), …)            // 전체 배치
2793  icStart(tones.map(t => Object.assign(icPayload(base), {style:t})), …)   // 톤 테스트
3029  icStart(failed.map(icPayload), …)          // 실패 재시도
3297  icStart([icPayload(c)], …)                 // 1컷 시험
3304  const pay = icPayload(c); pay.mode='ai'    // 제외 컷 강제 생성
3320  icStart([icPayload(c)], …)                 // 재생성
```

**(b) 서버가 분해 결과를 캐시해 병합하는가 → 아니다.**
`_generate_images_body:6545` 와 `_generate_videos_body:6983` 이 `p.get("cuts")` 를 그대로 쓴다.
서버 측 컷 저장소는 존재하지 않는다.

**(c) `컷작업_임시저장.json` 이 그 역할인가 → 아니다.**
`save_cut_draft`(5875)/`load_cut_draft`(5893)는 **프론트가 저장하고 프론트가 복원**하는
프론트 상태 스냅샷이다. 생성 경로(a)에 끼어들지 않는다. 드래프트에 `from_en` 이 남아 있든
없든 결론은 같다 — 어차피 `icPayload` 를 다시 통과해야 서버로 간다.

**결정적 실험 (5분, 코드 수정 전에 할 것):**
`main.py:6664` 가 배치마다 출력 폴더에 **`_프롬프트.json`(실제 조립된 프롬프트 전문)** 을 남긴다.

```
1. 「모아이」 컷 13(versus) 또는 컷 2(scale) 한 장만 [재생성]
2. 그 배치 폴더의 _프롬프트.json 을 연다
3. ANNOTATION_VERSUS / ANNOTATION_SCALE 문구(SPLIT / compare 대상)가 있는가?
   → 없으면 A-1 확정. 있으면 이 진단 전체가 무효
```

현재 디스크에 생성 배치가 하나도 없어(`_프롬프트.json` 전역 검색 0건) 실측으로는 못 닫았다.
**A-1 을 코드에 반영하기 전에 이 실험을 먼저 하라** — 4장 오진 패턴("데이터 흐름 끝까지 안 따라감")의
반대편 오류, 즉 "정적 추적만 믿고 실측을 건너뜀"을 피하는 유일한 방법이다.

> 참고로 「모아이」 컷 13 의 상하 분할이 살아 있었던 것은 A-1 의 반례가 **아니다.**
> `subject_en` 자체에 `"the frame split into two horizontal halves…"` 가 들어 있어 이미지가 그린 것이고,
> `anno_label` 의 `MYTH / REALITY` 는 `annotation_block` 이 `return ""` 하는 순간 같이 죽는다
> (`versus_labels` 가 그 안에서만 호출됨, 2465). **분할은 살고 라벨만 죽는 비대칭**이 오히려 A-1 의 증거다.

### A-2 — 채택, 그러나 최하위

## 3. 버킷 B — 틀렸거나 위험한 것

### B-2 ★ — 걱정 3개 중 2개 기각, 3번째가 진짜이고 **문안이 그걸 안 막는다**

**기각 ①: `SUBJECT_LOCK` 충돌 — 없다.**
`SUBJECT_LOCK`(1891)은 *"스타일이 **무엇을 보여줄지**를 바꾸지 마라, 맨 위 SUBJECT 를 그대로 렌더하라"*
이다. 그래픽을 `subject_en` 에 넣으면 그래픽은 **보호 대상**이 되지 충돌하지 않는다.

**기각 ②: 네거티브 프롬프트 충돌 — 없다.** (이건 3차가 묻지 않았지만 확인해둘 가치가 있다)
그래픽 컷은 `focus_en` 이 비어 주석 블록이 없으므로 `base_neg = NEGATIVE_CORE`(1913) 를 쓴다.
그 내용은 **글자·로고·손가락·얼굴 금지뿐이고 도형·발광을 금지하지 않는다.**
→ 순수 기하 그래픽을 구워도 네거티브와 부딪히지 않는다. B-2 의 이 방향은 안전하다.

**기각 ③: 정지 이미지에 이미 그려진 게이지 — 선례가 이미 있다.**
[3-1] 이 홀로그램에 대해 **정확히 같은 방식**을 쓴다(L2931-2933: 완성형으로 굽고 motion 은 점등·맥동만,
자가 조립 금지). 그리고 영상의 첫 프레임이 곧 그 이미지이므로, 낮게 채운 상태에서 시작해
`advances once toward its limit` 하면 차오름은 그대로 읽힌다. **3차의 완화안(`a bold filled portion`
을 낮게)을 문안에 명시로 못박아라** — `a short filled portion near its start` 정도로.

**진짜 문제: 코드 안전망을 벗어나는데, 그 대가를 문안이 안 갚는다.**

현재 구조에서 "그래픽 + 강조 도구" 이중 강조는 `strip_graphic_motion`(2322)이 **자동으로 걷어낸다.**
B-2 는 그래픽을 `subject_en` 으로 옮기는데, 그쪽을 검사하는 코드는 **존재하지 않는다.**
3차는 "[4]③ 을 지키면 `focus_en` 이 비고 → `_finish_split:6155` 가 `anno_kind` 를 강제 공백으로
만드니 안전"이라고 봤다. 맞다. **문제는 모델이 [4]③ 을 어겼을 때다.** 현재는 어겨도 코드가 구제하고,
B-2 후에는 **어기면 탐지 불가능**해진다. 순수 손실이다.

**해법은 이 코드베이스가 이미 두 번 쓴 패턴이다:**

```python
main.py:1171  is_holo_cut(cut)      → subject_en/motion 에 "hologram" 이 있으면 홀로그램 컷
main.py:1179  is_exploded_cut(cut)  → "exploded view" 가 있으면 분해뷰 컷
              (둘 다 _finish_split 6178-6188 에서 focus/measure/anno_kind 강제 공백)
```

지침 [5-2] 는 이를 위해 *"반드시 영어로 `shown in a compact exploded view` 라는 말을 넣어라
(이 문구로 시스템이 분해뷰 컷을 알아본다)"* 라고 **모델에게 대놓고 요구한다.**

→ **B-2 문안에 고정 영문 마커를 의무화하라.** 예:
> `subject_en` 에 붙이는 그래픽 구는 반드시 `already drawn as a flat cyan graphic overlay` 로 시작하라
> (이 문구로 시스템이 그래픽 컷을 알아본다).

이러면 나중에 3줄짜리 `is_graphic_cut()` 게이트로 홀로그램·분해뷰와 동일하게 강제 공백을 걸 수 있다.
**마커 없는 B-2 는 채택하지 마라.**

### B-3 — 예외 조항 대신 예시 추가가 맞다. 대안(캐논 뒤로 붙이기)은 **반대**

**전반부(진행형 대상):** E6 지적이 옳다. 목마 예시 컷B(`split open lengthwise revealing the hollow
interior`)가 상태 변화를 이미 시연하므로 **규칙은 충분하고 예시가 부족한 것**이다.
446줄에 규칙을 더 얹기보다 L2883 예시를 진행형 대상 하나로 교체·증설하는 쪽이 낫다.
"자문: 첫 컷과 마지막 컷에 똑같이 붙여도 둘 다 말이 되는가?" 이 한 줄은 남겨라 — 짧고 검사 가능하다.

**후반부(화각 어긋남) — 유지하되, 대안은 기각.**
"캐논을 `subject_en` **뒤쪽**에 붙이자"는 안은 **캐논이 작동하는 이유 자체를 없앤다.**
이미지 모델이 앞머리를 강하게 따르는 성질이 바로 캐논을 앞머리에 두는 근거이고,
실산출물에서 캐논이 8컷 동일하게 유지된 것도 그 위치 덕분이다. 뒤로 옮기면 컷마다 해석이 갈린다.
클로즈업 문제는 **위치가 아니라 길이**로 풀어야 한다 — 3차의 원안("화각과 어긋나면 줄여 써라")이 옳다.

### B-4 — 채택하되 인과가 약하다

"enum 불일치 → 모델이 enum 을 구속력 없는 것으로 취급 → `tabletop` 을 지어냄"은 **증거 없는 연결**이다.
3차 스스로도 의심했는데, 의심이 맞다. 더 단순한 설명이 있다: 모델이 **미니어처/틸트시프트 톤을
필요로 했고 목록에 없어서 지어냈다.** enum 을 고쳐도 재발한다.

→ 대책을 둘로 나눠라:
1. enum 정정 + `"이 목록에 없는 값을 지어내지 마라 — 앱이 조용히 snap(폰카 스냅샷)으로 바꿔
   톤이 통째로 어긋난다"` (F6 근거로 정확)
2. **탈출구 명시**: `"목록에 없는 느낌이 필요하면 가장 가까운 값을 골라라 —
   미니어처·모형 느낌은 claysection, 테이블 위 실물은 labmacro."`
   2번이 없으면 1번은 "지어내지 마라"라고만 말하고 대안을 안 준다.

부속 질문(6종 제외)은 **제외가 맞다** — 위 F7 참조.

### B-5 — 채택. 코드와 정확히 일치하며, 근거를 문안에 넣어라

`ANNO_SPAN_KINDS = {hud, measure, arrow, flow, route}`(1991) 이고 `_finish_split:6165-6166` 이
그 밖의 도구에서는 `from_en`/`to_en` 을 **한쪽만 와도 둘 다 버린다.**
→ 문안: `"위 넷 외에는 전부 빈 문자열이다 — 채워도 앱이 버린다."` (버린다는 사실을 알려주면
모델이 "혹시 몰라 채우는" 행동을 멈춘다)

### B-7 — 채택. **분량 증가라는 반론은 성립하지 않는다**

3차의 자기반론("실산출물 2편 모두 사고 미발생 → 분량만 늘리는 것 아닌가")은 두 군데서 틀렸다.

1. 현재 L2993 문장 *"(4컷을 넘기면 코드가 **약한 컷부터** 자동으로 끈다)"* 는 **사실과 다르다.**
   `_rank`(2605-2609)의 tie-break 는 컷 번호 오름차순이므로 **동급이면 뒤 컷부터** 꺼진다.
   이건 규칙 추가가 아니라 **오기 수정**이다.
2. 「모아이」는 `focus_en` 4개로 **상한에 정확히 닿았다**(컷 2·5·8·13). 한 컷만 더 켰으면
   rank 1 중 번호 최대인 **컷 13(versus, 영상 전체의 회수 컷)** 이 꺼졌다. 마진 1이다.

### B-8 — 채택하되 한 줄이 위험하다

> `subject_en 이 빈 컷에서는 이 값이 그대로 영어 프롬프트 자리로 들어간다`

이 문장은 **폴백의 존재를 모델에게 알려주는 것**이라, "짧은 컷은 subject_en 을 비우고 scene_ko 로
때워도 되는구나"라는 여지를 만든다. 그러면 한글이 영어 프롬프트 자리로 들어간다 —
지침 6장 제약이 금지한 바로 그 사고다.

→ 교체: `"subject_en 은 어떤 경우에도 비우지 마라 — 비면 이 한글 문장이 영어 프롬프트 자리로
들어가 이미지가 통째로 어긋난다."` 사실은 같이 알려주되 **금지형**으로 써라.

### B-9 vs B-10 — B-9 택일

**B-9 를 택한다. 근거:**
- 실패가 **컷 단위**로 발생한다. 「역타」 컷 9 는 `plan` 의 캐논 계획이 맞았어도 그 컷에서
  어긋난 것이다. `plan` 은 계획과 컷의 불일치를 잡지 못한다.
- B-10 의 `변하는것` 항목은 B-9 형식의 `캐논: [대상, 주의점]` 에 그대로 흡수된다.
- `plan` 의 원 명분(캐논 표류 방지)은 이미 반박됐다(E2). 남은 건 검수 편의뿐인데,
  그 목적이라면 컷 옆에 붙는 쪽이 대조 비용이 낮다.

**토큰:** B-9 는 컷당 40~60자 한글 ≒ 출력 +10% 안팎. 「모아이」 기준 6~7k → 7~7.7k 토큰.
회당 250원 기준 +25원. 컷 하나 재생성 판단을 한 번 앞당기면 회수된다.

**단, B-9 문안에 한 줄 추가하라:** `"영어 필드와 모순되면 영어가 아니라 이 줄을 고쳐라"` 가 아니라
**반대**여야 한다 — `"이 줄은 영어 필드를 요약한 것이다. 둘이 다르면 영어 필드가 틀린 것이다."`
검수자가 무엇을 신뢰해야 하는지 정해두지 않으면 이 필드는 알리바이가 된다.

## 4. 4장(오진 목록)에 대한 재반박

### E9 는 **3차가 틀렸다** — 같은 유형의 오진이 4장 안에서 재발했다

> E9 판정: *"'훅 컷은 measure_en 없으면 강조가 안 나온다'는 의존관계가 미기재 → 실제 의존 방향은
> 반대이고 [4-b] L3000-3001 에 이미 명문화돼 있음(measure 는 focus 필요)"*

**두 개의 서로 다른 규칙을 하나로 합쳤다.**

```python
main.py:2548-2557  anno_for_cut()
    beat = cut.get("beat") or ""
    if beat in ANNO_SKIP_BEATS:                       # {"hook", "closing"}
        if beat == "hook" and (cut.get("measure_en") or "").strip():
            return auto_val                            # ← 수치가 있어야 통과
        if beat == "hook" and glow and (cut.get("focus_en") or "").strip():
            return auto_val                            # ← 또는 glow 도구
        return ""                                      # ← 그 외 훅은 전부 무음
```

- **[4-b] L3000-3001** = *작성 규칙*: "`measure_en` 은 `focus_en` 이 채워진 컷에만 넣어라."
  (수치를 새기고 싶으면 가리킬 대상도 줘라)
- **코드 게이팅 2548-2557** = *게이팅 규칙*: "`beat=hook` 컷은 `measure_en` 이 없으면
  `focus_en` 과 `anno_kind` 가 멀쩡해도 주석이 통째로 꺼진다." (glow 예외 별도)

둘은 방향도 대상도 다르다. 후자는 **[4-a] L2986-2987 에 작성자 관점으로 반쯤 적혀 있을 뿐**
("예외: 훅에서 숫자 하나가 결정적일 때는 focus_en 과 measure_en 을 함께 채워라"),
"안 채우면 꺼진다"는 결과는 어디에도 없다.

**실증:** 「모아이」 컷 2 는 `beat=hook` + `anno_kind=scale` + `focus_en` 채움이다.
이 컷의 강조가 살아난 유일한 이유는 `measure_en="70t"` 이다. `70t` 을 지우면
(그리고 `scale` 은 glow 가 아니므로) **아파트 비교 홀로 전체가 무음이 된다.**

→ **E9 를 오진 목록에서 빼고, "훅 게이팅 명문화"를 B 버킷에 되살려라.** 한 줄이면 된다:
> `beat=hook` 컷의 강조는 `measure_en` 이 있거나 `anno_kind=glow` 일 때만 화면에 나온다.
> 훅에 `scale`·`versus` 를 쓰려면 `measure_en` 을 반드시 함께 채워라.

## 5. 질문에 대한 답

**1. A 를 범위에 넣는가** → **A-1 만 같이. 나머지 A 는 별도 건.**
A-1 을 빼면 B-1·B-5 가 무효이고, 그 둘은 B 버킷의 논리적 전제다. 반면 A-2·A-3·A-4 는
B 와 독립이며 기존 산출물의 재현성을 건드린다. **단 A-1 은 4장에 적은 "결정적 실험"
(`_프롬프트.json` 확인)을 먼저 통과시킨 뒤에 넣어라.**

**2. B-2 의 부작용** → 3개 중 2개는 기각(SUBJECT_LOCK 무충돌, 게이지 선례 존재).
세 번째(코드 안전망 상실)만 실재하고, **현재 문안이 그걸 안 막는다.**
고정 영문 마커 의무화로 해결하라(3장 B-2 참조). 마커 없으면 채택 보류.

**3. B-3 이 필요한가** → **예외 조항 대신 예시 교체가 맞다.**
"자문" 한 줄만 남기고, 진행형 대상 예시를 L2883 에 증설하라.
"캐논 뒤로 붙이기" 대안은 **캐논이 작동하는 메커니즘을 없애므로 기각.**

**4. B-9 와 B-10 이 중복인가** → 중복이다. **B-9 택일.** 근거는 3장 참조.

**5. 4장 오진 패턴이 3장에 남아 있는가** → **3건 남아 있다.**
- **E9 자체가 재발**(위 4장). "방향 혼동"을 지적하며 방향을 혼동했다
- **F5** — 코드가 이미 양쪽을 처리하는데 "이름 분열이 사고 조건"이라고 인과를 이었다.
  4장의 "데이터 흐름 끝까지 안 따라감"의 거울상: **끝까지 따라가지 않고 위험을 과대 추정**
- **B-4** — "enum 불일치 → tabletop 지어냄" 역시 증거 없는 인과

`from_en`/`to_en`/`compare_en`/`flow_of` 소멸은 **직접 추적해 확인했다**(4장 A-1 의 (a)(b)(c)).
다만 정적 추적의 한계가 있으므로 실험 절차를 붙였다.

**6. 놓친 것 — [5-4] reveal 에서 1건 나왔다**

```python
main.py:2725-2731  cut_reveal(cut)
    r = (cut.get("reveal") or "").strip().lower()
    if r in REVEAL_LINES: return r
    return "full_section" if cut.get("shot") == "cutaway" else ""
```

`reveal` 이 비어 있어도 **`shot="cutaway"` 면 코드가 `full_section` 으로 승격한다.**
`_finish_split:6150-6151` 은 `reveal` 이 **있을 때만** `shot` 의 `cutaway` 를 지우므로,
`reveal=""` + `shot="cutaway"` 조합은 그대로 통과한다.
→ **[5-4] 의 "한 영상에 리빌 2~3컷" 예산 밖에서 단면 컷이 생긴다.**
[5-4]② 가 *"'cutaway' 라고 쓰지 마라"* 로 반쯤 막지만, 그 문장은 **reveal 을 쓴 컷에만** 걸려 있다.

덧붙여 `is_cut_open()`(2734-2736)은 **`xsection` 톤 컷도 '연 컷'으로 친다** — 즉 `reveal` 을
비워도 `style=xsection` 이면 영상에 기하 잠금이 걸린다. 지침은 이 사실을 말하지 않는다.

→ 문안 제안 ([5-4] 규칙 ②를 교체):
> `shot` 에 `cutaway` 를 쓰지 마라 — `reveal` 을 비워도 앱이 전체 단면으로 읽어, 네가 세지 않은
> 리빌 컷이 하나 더 생긴다. 속을 여는 것은 언제나 `reveal` 로만 말하라.
> `style=xsection` 컷은 `reveal` 이 비어 있어도 '연 컷'으로 세어라.
