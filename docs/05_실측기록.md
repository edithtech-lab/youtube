| 배치 | 결과 |
|---|---|
| **2명 · 크게** | **완전 유지.** 자세·인원 그대로, 4초 내내 **얼굴이 안 생겼다** (`VIDEO_CAST_LOOK` 실증) |

**결론** — 인물이 셋 이상이거나 작게 잡히면 아무도 움직이지 마라. 부감·와이드로 여럿을

> "뒤쪽은 옅은 안개에 잠겨 실루엣만" 을 적으면 일관성 흔들림을 가릴 수 있다.

## whitecast·greycast 발광 (2026-08-15)

레퍼런스 20.6분(`레퍼런스_D8nt3dt8vT4/`)을 4초 간격 309프레임으로 갈라 측정했다.

| | 측정값 |
|---|---|
| 컷 | 약 181컷 · 평균 6.9초 / **중앙값 5.5초** · 분당 8.8컷 |
| 세계 밝기 | 평균 **100/255** — 밝은 흰 세계가 아니다 |
| 검정 배경 컷 | **17%** · 밝은(설원) 컷 13% |
| 세계 색조 | 어두운 채도색 85% 컷, 그중 시안·파랑 90% → 차가운 청록회색 |

**측정 함정 둘** — 같은 실수를 반복하지 마라:
- "발광 34%"는 **흙 단면의 갈색 질감**을 발광으로 잘못 셌다
- 첫 채도 측정은 **인물의 남색 의상**을 강조색으로 잘못 셌다
- → 발광만 재려면 **밝기 150 초과 + 채도 35% 초과**로 걸러야 한다

**톤 문구가 발광을 스스로 막고 있었다.** `No colour anywhere except the neutral scale…` 와
강조 블록의 `A bright cyan (#22D3EE)…` 가 한 프롬프트 안에서 충돌했다. 모델은 이럴 때
절충해서 흐린 회분홍을 그리거나 강조를 지운다 — 컷마다 결과가 달랐던 원인이다.

**고친 뒤 실측** (2K 샘플 6장):

| 컷 | 조건 없이 열었을 때 | 조건화 후 |
|---|---|---|
| `whitecast` 강조 없음 | 채도 **19.30%** (감시탑이 제멋대로 빛남) | **0.00%** |
| `greycast` 강조 없음 | 3.74% | **0.00%** |
| `extent` 강조 있음 | 13.77% | 9.62% (유지) |

색 예외는 **"강조 지시가 있을 때만, 그 색으로만"** 이라고 조여야 한다. 그냥 열면
모델이 발광 여부와 색을 스스로 정해 컷마다 달라진다.

**`almost shadowless` 는 흰 모형의 적이었다.** 그림자가 형태를 읽히게 하는 유일한 수단인데
그걸 지우고 있었다. 낮은 각도 방향광 + 긴 그림자로 바꾸자 면 구분이 살아났다.

**`extent` 신설 근거** — 레퍼런스의 울타리 컷은 `glow`(덩어리 하나)·`count`(점)·`zone`(평면
영역) 어느 것으로도 안 된다. 선형으로 뻗은 것이 **얼마나 멀리 가는지**가 요점이라 별도 도구다.

## 조립 강조 CLEAN→INFO (2026-08-18)

레퍼런스 두 편(피렌체 돔·티거 88mm)의 "그래픽이 나레이션에 맞춰 그려지는" 효과를 역추적해
도입했다. 정체는 **시작+도착 프레임 보간**: CLEAN(강조 없음)에서 출발해 INFO(강조 구움)를
도착 프레임으로 걸면 그래픽이 클립 안에서 조립된다.

| 실험 | 결과 |
|---|---|
| draw (그리라고만 지시, 목표 없음) | 2.5초까지 빈 화면 — **기각** (2026-08-16) |
| Seedance 4초 + INFO 도착 | 4단계 조립 완주, 끝 상태 고정 ✅ |
| Veo 4·6초 + 도착 프레임 | **400 통째 거부** — 보간은 8초 전용 |
| Veo 8초 + INFO 도착 | 조립 완주, 선이 가장 얇고 정밀 ✅ (lite 도 됨) |
| Veo 말 지시만 (목표 없음) | 4단계 중 2단계에서 멈춤 |
| Seedance 8초 동일 프롬프트 | 조립되나 **중간 도형 발명** (UFO 같은 이중 고리) |

**어휘 함정**: 프롬프트의 `anchor dot` 을 Seedance 가 문자 그대로 **⚓ 닻 아이콘**으로
그렸다 (같은 문구를 Veo 는 점으로 해석). → 조립 문구는 `small glowing dot` 로 쓰고
"다른 도형·아이콘·심벌 발명 금지"를 명시한다 (`VIDEO_ASSEMBLE_TMPL`).

**기존 방식의 3초 소실**(화살표가 4초 클립에서 3초에 사라짐, slowpush 로도 못 막음)이
조립 방식에선 구조적으로 불가능하다 — 도착 프레임에 그래픽이 있으므로.

**INFO 편집 패스**: CLEAN 을 참조로 "강조만 얹어라" 편집이 구도를 보존했다 (`INFO_EDIT_HEAD/TAIL`).
graph 도구(축+눈금+곡선+워시)는 이 실측에서 문구가 검증돼 21번째 도구로 등록됐다.

## 참조에 없는 것이 끼어드는 문제 — 문구 3곳 개정 (2026-08-21)

포크 쪽 재생성 사유 집계에서 **인물 일관성은 0건**이고 1위가 **잡인물 7컷**, 2위가
**배경 오인 4컷**, 3위가 **소품 오인 2컷**이었다. 참조 이미지가 있는 것은 안 깨지고
**참조에 없는 것만 깨진다**는 뜻이라, 그쪽을 막는 문구를 넣었다.

- `REG_COUNT_LINE` + "No unnamed people appear anywhere **unless the SUBJECT description
  above explicitly places them**" — 무조건 금지면 군중 컷이 깨지므로 조건을 문장 안에 뒀다.
  코드 분기도 키워드 매칭도 없다.
- `CHAR_PICK_LINE` 교체 — 옛 문구 "the other characters are not in frame" 은
  **화면에 없는 인물을 이름으로 부르는 부정형**이었다. 인원수를 숫자로 못박고
  (`exactly one person` … `exactly four people`) 엑스트라는 긍정형으로 돌렸다.
- 지침 `[1]-7` 에 상징 소품은 형태 묘사로 · 나라·시대를 안 쓰면 흐른다(한옥 사고) 추가.
- 지침 `[4-c] chars` 에 시트 4명 상한·동일복장 허용·단역 라벨 규칙 추가.

## 무기 채널 피드백 반영 — intercept·deflect 신설, 톤 기본값 교정 (2026-08-21)

무기 편 제작 중 받은 피드백 네 건 중 셋을 처리했다. 예시는 `_실험/tone_cand/`.

**① intercept 신설** — `trajectory` 는 아크 하나만 그리고 문구가 `never a second impact` 로
두 번째를 **명시적으로 금지**한다. 요격·단 분리·종말 유도를 그릴 도구가 없었다.
끝점 없이 `focus_en` 한 구로 받고, 두 경로가 한 점에서 만나 그 지점만 밝게 터진다.
실측(techteal, 함상 요격): 두 아크가 만나고 만남점이 밝게 플레어 — **성공**.

**② deflect 신설** — 경사장갑·공간장갑·성형작약이 전부 "들어와서 표면에서 꺾여 되나가는"
그림인데 목록에 없었다. `arrow`(꺾임 없는 한 방향) · `flow`(출발→도착) · `loadsplit`(둘로
갈라져 우회) 어느 것도 아니다. 갈리는 지점을 문구와 지침에 못박았다.
실측(techcool, 경사장갑): 접점 플레어 + 꺾인 출사각 — **성공**.
둘 다 유성형 문법(경로는 잔광, 밝은 머리만 달림)을 따르고 조립 단계도 넣었다.

**③ [3] beat 기본값 줄 교정** — 이게 제일 컸다. 기본값 줄이 `hook→docu3d 또는 cine` 로
고정이고 techteal·techcool 은 **아래 서술 문단에만** 있었다. 분해기는 기본값 줄을 먼저 읽는다.
결과가 K9 편 톤 분포다 — **docu3d 8 / blueprint 3 / xsection 1, docu3d 67%, 기술 전용 톤 0컷.**
사용자 결정("무기는 대부분 techteal 로")을 반영해 **기본을 techteal 로, 내부 구조·부품을
읽어야 하는 컷만 techcool** 로 못박고 "docu3d 는 이 채널의 기본값이 아니다"를 명시했다.
→ 교훈: **지침에 있다 ≠ 기본값 줄에 있다.** 서술 문단은 기본값 줄을 못 이긴다.

**④ 열상·야시 톤** — 보류(사용자 결정).

## 구운 화살표가 영상에서 사물처럼 움직인다 — arrow 를 영상 전용으로 (2026-08-21)

사이클론 편 #6 (원뿔 안벽을 감아 내려가는 톱밥, `anno_kind: arrow`, 1080p·6초) 두 판 판독.

| 판 | 결과 |
|---|---|
| v1 | 1.2초부터 형태가 변하고, 4.8초에 **거대한 흰 직선 화살표로 변신**해 원뿔 아래를 관통 |
| v2 | 1.2초에 **위아래로 뒤집히고**, 2.4초부터 원뿔 밖으로 튀어나가 프레임 왼쪽 위에 떠 있음 |

**잠금 문구는 최대로 걸려 있었다** — `locked to the scene in perspective: same position, same
size, same angle. Zero drift, zero duplication, zero morphing` + `never grows, shortens,
retracts, extends` + 카메라 `locked-off` + 템포 `slow and deliberate`.
강조 컷 보호 장치(`CAMERA_LOUD` 강등·템포 강등)가 전부 작동한 상태에서 실패했다.

**핵심 관찰: 같은 클립에서 톱밥과 장면은 멀쩡했다.** 톱밥은 자연스럽게 흘러내려 바닥에
쌓였고, 깨진 것은 **구운 그래픽뿐**이다. 사용자 지적("애초 이미지에 박혀 있어서 그런 것
아니냐")이 정확했다 — 구운 그래픽은 6초 내내 **보존해야 할 부품**이 되고, 장면이 바뀌는
동안 기준을 잃는다.

원인 두 겹 —
① **arrow 는 빛이 아니라 판때기다.** 문구가 `one flat matte arrow of solid opaque colour,
   like a cleanly printed sign` 이라 모델이 장면 안의 **물체**로 읽고 함께 애니메이션한다.
   같은 조건에서 `spin` 은 `a thin luminous helical sweep … hugging the surface` 라
   표면의 일부로 읽힌다.
② **나선 형태.** 3D 곡면을 한 바퀴 이상 감아 도는 경로는 프레임마다 다시 그려야 한다.

**반영 두 가지**
· `ANNO_IMAGE_SKIP` 에 `arrow` 추가 — 이미지에 굽지 않고 영상에서 `arrow_draw` 로 그린다.
  ⚠ 영상을 안 만드는 컷에서는 화살표가 사라진다.
· 지침 `[4-d] arrow` 에 "표면을 감아 도는 나선·소용돌이는 `spin` 이다" 명시.
  완만하게 휘는 것까지는 arrow 가 받되, **한 바퀴 이상 감기면 금지**(사용자 결정).

**아직 미검증**: 영상이 그리는 화살표(`arrow_draw`)가 2K 이미지에 굽는 것만큼 원근을
정확히 잡는지. 720p·1080p 자가 작도라 각도가 어긋날 수 있다 — 다음 편에서 확인할 것.
