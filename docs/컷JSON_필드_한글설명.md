## 0. 큰 그림 — 값이 어디로 흘러가나

```
컷 JSON (컷당 24개 필드)
   │
   ├─→ ① 이미지 프롬프트 (영어 약 3,500자) ──→ 2K 이미지
   │      subject_en 이 전부를 결정한다
   │
   ├─→ ② 영상 프롬프트 ──→ 720p 영상
   │      **시작 이미지가 장면을 결정하고, 프롬프트는 "무엇이 변하나"만 말한다**
   │      → subject_en 은 영상 프롬프트에 안 들어간다 (이미지가 이미 정의했으므로)
   │
   ├─→ ③ 파일명 · 자막 타이밍 · 클립 길이
   └─→ ④ 사람이 읽는 검수용
```

**가장 중요한 원칙 하나:** 앱은 완성된 영어 프롬프트를 LLM에게 받지 않는다.
질감·색·카메라·강조 문법은 **앱이 갖고 있고**, JSON은 **부품 값**만 채운다.
그래야 편마다 같은 결이 나온다.

## 1. 필드별 상세

### ■ 뼈대

| 필드 | 무엇인가 | 어디로 가나 |
|---|---|---|
| `no` | 컷 번호 | 파일명 앞자리 · 순서 |
| `line` | **대사 원문 그대로** | 자막 · **글자 수로 클립 길이(4·6·8초) 결정** |
| `beat` | 이 컷의 역할 8종 | **카메라 자동 선택** + 강조 게이팅 |
| `type` | product / principle / … 6종 | **`product` 만 의미 있음** (실물 검색 배지). 나머지는 사실상 무효 |

`line` 은 **한 글자도 바꾸면 안 된다.** 자막·음성 타이밍이 글자 수로 정렬되므로,
한 문장이 빠지거나 달라지면 뒤 컷 전체 타이밍이 밀린다.

### ■ 이미지를 결정하는 것

| 필드 | 무엇인가 | 어디로 가나 |
|---|---|---|
| **`subject_en`** | **무엇이 찍혔는지 영어로.** 재질·색·상태까지 | 이미지 프롬프트 맨 위 `SUBJECT:` 자리에 **그대로** |
| `place_en` | 장소 | `Setting:` 줄 |
| `weather_en` | 공기·빛 (먼지·안개·물보라) | `Atmosphere:` 줄 |
| `style` | 톤 (종류는 `docs/_현황.md`) | 톤 문구 + 톤별 네거티브 + 얼굴 정책 + 참조이미지 분기 |
| `shot` | 화각 7종 | `Shot:` 줄 + **카메라 선택 근거** |
| `reveal` | 속을 어떻게 여는가 (종류는 `docs/_현황.md`) | 절개 지시 + **영상 기하 잠금** |
| `evidence` | 아는 것/추정한 것 3종 | 복원부 표현 방식 |
| `chars` | anime 캐릭터 라벨 | 캐릭터 시트에서 누구를 뽑을지 |

> **`subject_en` 이 이미지의 90%다.** 톤·화각은 "어떻게 보이나"를 정할 뿐,
> "무엇이 찍혔나"는 오직 이 문장이 정한다. 비어 있으면 `scene_ko`(한글)가
> 그 자리에 들어가 이미지가 통째로 어긋난다 — 그래서 절대 비우면 안 된다.

### ■ 영상을 결정하는 것

| 필드 | 무엇인가 | 어디로 가나 |
|---|---|---|
| **`motion_en`** | **시간에 따라 무엇이 변하나** 영어 한 문장 | 영상 프롬프트 `Motion:` 자리에 **그대로** |
| `chain` | 앞 컷과 이어지는가 | 도착 절 + 체인 카메라 시퀀스(push→riseorbit→pullup→orbit) |

영상 프롬프트에 **자유 텍스트는 `motion_en` 하나뿐**이다.
카메라·유지절·템포·오디오·금지사항은 전부 앱이 가진 고정 문구다.

### ■ 강조(화면 위에 그려지는 표시)

| 필드 | 무엇인가 | 조건 |
|---|---|---|
| `focus_en` | **주석이 가리킬 단 하나** | **비면 강조 전체가 꺼진다** (마스터 스위치) |
| `anno_kind` | 어떤 도구로 그릴까 17종 | `focus_en` 이 있어야 유효 |
| `measure_en` | 화면에 새길 수치 | 12자 · 라틴/숫자만 (한글은 통째로 지워짐) |
| `anno_label` | 옆에 새길 영문 이름 | **16자** 초과 시 첫 단어만 남음 |
| `from_en`/`to_en` | 선의 시작·끝 | `measure·arrow·flow·route` 넷에서만. 나머지는 채워도 앱이 버림 |
| `compare_en` | 비교 대상 | `scale`(옆에 놓을 것) · `versus`(위 칸의 통념) |
| `flow_of` | 무엇이 흐르나 | `flow` 에서만. **색이 여기서 정해진다** (찬 공기=하늘색, 열=주황) |

**강조를 붙이면 그 컷은 자동으로 차분해진다** — 카메라가 `still`/`slowpush` 로 묶이고
템포가 `calm` 으로 바뀐다. 치수선·화살표가 구조에 고정돼 있어서 카메라가 밀고 들어가면
화면 밖으로 밀려나기 때문이다(2026-08-12 실측: 6초 클립에서 화살표가 3초 만에 사라짐).

### ■ 사람용

| 필드 | 무엇인가 |
|---|---|
| `scene_ko` | **파일명이 된다 — 앞 12자만 남는다.** 15자 내외 명사구 |
| `검수_ko` | 붙여넣기 전에 사람이 읽는 한 줄. **앱은 안 읽는다** |
| `search_ko` | `type=product` 일 때 실물 검색어 |

## 2. 규칙 전체 — 한글 요약

### [0] 대본 형식 자동 인식
대본을 보고 셋 중 하나로 판별한 뒤 그에 맞게 분해한다.
- **A 건축사전형** (원리 분석 — 건축물·무기·제품): 모순 훅 → 제약 → 발상 뒤집기 → 해법 → 비유
- **B 썰쇼츠형** (사건 서사): 결과 선공개 → 결핍/위기 → 반전 → 감정 낙인
- **C 작품요약형** (만화·영화 한 편): 표로 들어오면 그 나눔을 그대로 존중. `style` 전부 anime

### [1] 분해 규칙
1. 한 컷 대사는 **41~83자** (낭독 4~8초). 짧은 문장은 앞뒤와 묶는다
2. **첫 문장(훅)은 반드시 독립 컷**
3. **`chain`(이어짐)** — 앞 컷과 같은 공간·같은 대상일 때만 true. 한 영상 묶음 2개, 묶음당 3컷
4. **전환의 대비** — `chain=false` 는 장면 전환 지점. 거리·시점·밝기를 바꿔라
5. 숫자·등급을 글자로 그리지 마라. 그 숫자가 뜻하는 상태를 사물로
6. 브랜드·로고 금지. 얼굴은 알아볼 수 없게 (인물 톤 제외 — 어느 톤인지는 `docs/_현황.md` 의 얼굴 정책 열)
7. **반복 피사체 캐논** — 2컷 이상 나오는 주인공은 상세 영어 묘사 한 구를 확정해
   모든 컷 `subject_en` 앞머리에 **토씨 하나 안 바꾸고 복사**
   · 인물도 캐논 대상 (얼굴 말고 실루엣·의상·소지품으로)
   · 진행되는 것(공정 중 생기는 기둥 등)은 캐논에 넣지 마라
   · 화각과 어긋나면 줄여 써라 (클로즈업 컷 앞머리에 전경 묘사 → 와이드로 나온다)
8. **`subject_en` 에 톤·매체 어휘 금지** — `cinematic` `black-and-white` `drone shot` 같은 말을
   쓰면, 화면에서 톤을 일괄로 바꿔도 그 컷만 원래 톤으로 남아 화면이 섞인다

### [2] beat — 8종
`hook · context · constraint · despair · pivot · solution · analogy · closing`
카메라가 여기서 갈린다: `closing→pullup · solution→pushdown · pivot→push`

### [3] beat별 톤 기본값
`docu3d` 가 대표 톤(전체의 절반). 보조 톤은 3연속 금지.
현장 이야기 중엔 `labmacro·xsection·tech3d` 로 빠지지 마라(배경이 비어 장소를 잃는다).
- 치수·구조가 요점 → `claysection` · 위에서 본 배치 → `planline`
- 작전·지형·건물 배치를 한눈에 → `tabletop`(미니어처, 카메라 자동으로 묶임)
- 인물이 끌고 가는 컷 → `game`(엔진 룩) / `story3d`(영화 렌즈) / `toy3d`(피규어)
  **한 영상에서 인물 톤은 하나로 통일**

### [3-1] 홀로그램 재구성 — 한 영상 1~2컷
실사 위에 시안 와이어프레임을 겹쳐 **지금 없는 것**을 재구성.
쓰는 조건 넷: ①과거 재구성 ②투시 ③기각되는 대안 ④스케일 비교
· **완성된 모습을 `subject_en` 에 써서 이미지에 굽는다.** 무에서 조립되는 과정은 금지
· `motion_en` 은 반드시 홀로그램을 **다시 언급**해야 한다(안 하면 영상이 지운다)
· 배경·실물은 끝까지 100% 실사. 화면 전체를 덮으면 다큐가 아니라 SF가 된다

### [4] motion_en
모든 컷에 채운다. 카메라는 쓰지 마라(따로 정해진다).
**글자 없는 그래픽 애니메이션**은 2단으로: 도형의 완성형은 `subject_en` 에 굽고
(`already drawn as a flat cyan graphic overlay,` 로 시작), `motion_en` 엔 그 도형의 변화만.

### [4-a~e] 강조
- **`focus_en`** — 대사가 "이걸 보라"고 말하는 바로 그것. 한 영상 3~4컷
- **`measure_en`** — 이 컷의 요점인 수치만. `focus_en` 이 있어야 화면에 나온다
- **`anno_kind`** — 17종. 대사의 논리에 맞는 도구를 고른다
  (`arrow` 방향 / `flow` 여정 / `route` 사람이 지난 길 / `reject` 실패 / `versus` 통념 뒤집기 /
   `void` 빈 공간 / `scale` 크기 비교 / `measure` 치수 …)
- **`from_en`/`to_en`** — 두 점을 잇는 넷에서만. 끝점이 없으면 모델이 축을 찍는다
- **훅 컷의 강조는 `measure_en` 이 있거나 `glow` 일 때만 화면에 나온다**

### [5-1] 인과는 한 단계만
영상 모델은 한 클립에 사건을 여러 개 시키면 **중간을 건너뛴다**(A→B→C 시키면 A→C).
형태: `[A의 동작], [B의 직접 반응]`. `then / next / finally` 로 잇지 마라.

### [5-2] 분해뷰
**분해된 상태를 이미지에 굽고**, `motion_en` 은 **직선 재조립 한 번**.
반드시 `shown in a compact exploded view` 를 넣어라(이 문구로 시스템이 알아본다).

### [5-3] 720p가 그릴 수 있는 것 / 없는 것
**필요한 그림은 2K 이미지에 굽고, 영상엔 '이미 있는 것의 변화' 하나만 맡겨라.**
- 되는 것: 이미 있는 굵은 띠 위의 밝은 앞머리 하나 · 밝기 변화 · 단단한 부품의 직선 이동 ·
  **큰 껍질 하나가 투명해지는 것** · 넓고 부드러운 스캔 띠
- 안 되는 것: 가는 발광선 · 와이어프레임 · 글자 · **고체를 통과하며 속을 만드는 절단면** ·
  가는 스캔선 · 갈래 번개 · 수천 개 미세 입자 · 동시에 두 흐름

### [5-4] reveal — 한 영상 2~3컷
`partial_cutaway`(기본값으로 먼저 검토) · `breakout` · `full_section` · `ghosted` · `layer_reveal`
- `shot` 에 `cutaway` 를 쓰지 마라 (reveal 을 비워도 앱이 전체 단면으로 읽는다)
- `style=xsection` 컷은 reveal 이 비어도 '연 컷'으로 센다

### [5-5] evidence — 문화유산 정직성
`solid`(현존) · `inferred`(근거 있는 추정) · `hypothetical`(가설 — 와이어프레임으로 표시)
모르는 것을 아는 것처럼 그리면 콘텐츠 신뢰가 깨진다.

### [출력] 글자 수 상한 — 넘으면 앱이 조용히 자른다
```
focus_en 140 · from_en/to_en 각 90 · compare_en (scale 90 / versus 110)
measure_en 12 (라틴·숫자만) · anno_label 16 (넘으면 첫 단어만)
scene_ko 는 앞 12자가 파일명
```

## 3. 자주 헷갈리는 것

### Q. 속을 열어 보이는 걸 분해기가 알아서 판단하나?

**그렇다.** `[5-4]` 가 *"대사가 내부·구조·속을 실제로 설명할 때만 고른다"* 고 지시하므로,
분해기가 **대본을 읽고 스스로** `reveal` 을 채운다. JSON에 따로 지시를 쓸 필요 없다.

**다만 대본에 단서가 있어야 잡는다.** "속을 갈라보면", "안에는", "겉은 석회암 속은 화강암"
같은 말이 대사에 있어야 한다. 없으면 분해기는 자를 이유를 모른다.

**그리고 컷 카드에서 직접 바꿀 수 있다.** UI에 편집 가능한 필드가 이만큼 있다:
```
톤(style) · 화각 겸 카메라 · 영상 길이 · 강조 방식 · 강조 도구 ·
subject_en · motion_en · focus_en · weather_en · scene_ko · reveal · evidence
```
→ 분해기가 1차로 채우고, **최종 결정은 사람이** 한다.

### Q. 겉면이 사라지고 속이 보이는 연출은?

한 컷 안에서는 **막혀 있다.** `reveal` 이나 `xsection` 이면 영상에 이 네거티브가 붙는다:
> *the object bending, melting, peeling open to reveal its inside; a moving cutting plane* 금지

720p가 절단면을 새로 그리면 뭉개지기 때문이다. **두 방법으로 푼다:**

1. **chain 두 컷** (정석) — 컷 A 겉면 온전 → 컷 B `reveal:ghosted` + `chain:true`.
   영상이 A에서 B로 '도착'하며 껍질이 사라지는 전환이 그 사이에 생긴다. 화질 손실 없음
2. **`ghosted` 만 잠금에서 빼기** (코드 수정 필요) — `[5-3]` 이 *"큰 껍질 하나가 투명해지는 것"* 은
   허용하고 있으므로, 절단면 이동과 구분하면 한 컷 안에서도 가능해진다

분해뷰도 같다 — 벌어지는 과정을 보여주려면 **컷 A 조립 → 컷 B 분해**로 나눈다.
