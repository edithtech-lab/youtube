# 영상화 두 갈래 — 컷 영상화 vs 자료 소스 탭

이 프로젝트에서 가장 자주 헷갈리는 지점이다. **탭이 두 개 있고, 둘 다 "이미지 → 영상"을
하지만, 코드는 거의 아무것도 공유하지 않는다.** 한쪽을 고쳐놓고 "영상화 고쳤다"고 말하면
절반만 맞다. 실제로 여러 번 그렇게 틀렸다.

```
  이미지 생성 탭의 [영상화]              자료 소스 탭의 [영상화]
  ────────────────────────              ────────────────────────
  _generate_videos_body                 _source_video
        │                                     │
        ▼                                     ▼
  _build_motion_prompt                  source_video_prompt
        │  MOTION_PROMPT_I2V                  │  SOURCE_MOTION
        │  _auto_camera (앱이 결정)            │  사용자가 직접 고름
        │  톤·리빌·체인·강조 게이팅 20여 개     │  톤별 모션 한 줄 + 고정 규칙
        ▼                                     ▼
  _archive_prev (NN_ 접두로 묶음)        _archive_one (정확한 경로 하나)
        └──────────────┬──────────────────────┘
                       ▼
            _gen_seedance / _gen_veo      ← 만나는 곳은 여기뿐
```

---

## 무엇이 다른가

| | **컷 영상화** | **자료 소스 탭** |
|---|---|---|
| 입력 | 컷 JSON 24필드 + 2K 이미지 | 이미지 한 장. **컷 개념이 없다** |
| 프롬프트 틀 | `MOTION_PROMPT_I2V` (이미지 있을 때) / `MOTION_PROMPT` (없을 때) | `source_video_prompt()` 가 문자열 조립 |
| 모션 문장 | `cut["motion_en"]` — LLM 이 컷마다 씀 | `SOURCE_MOTION[톤]` — 톤별 고정 한 줄 |
| 카메라 | **앱이 정한다** (`_auto_camera`) · 사용자가 고르면 그것 | **사용자가 고른다** · 안 고르면 고정 |
| 카메라 기본값 | 컷의 `shot`/`beat`/`type` 으로 자동 선택 | **고정** (`camera_fixed=True`) |
| 톤 잠금 | game·story3d·toy3d·greycast·whitecast·anime 각각 다른 절 | 없음 |
| 리빌·단면·분해뷰·체인 | 전부 있음 | 없음 |
| 강조 유지 | `VIDEO_TEXT_KEEP` 로 이미지의 글자를 지킴 | 글자 금지 |
| 보관 | `_archive_prev(outdir, no)` — `NN_` 접두 묶음 | `_archive_one(path)` — 그 파일만 |
| 저장 위치 | 편별 프로젝트 폴더 `이미지/` | 날짜별 `자료이미지/YYYYMMDD/` |

**저장 위치가 다른 이유**: 자료 소스는 본편에 딸린 게 아니라 여러 편에 두루 쓰는 재료다.
편별로 흩어 놓으면 다시 못 찾는다. (`source_outdir()` 주석)

## 컷 영상화 — `_build_motion_prompt`

### 첫 갈림길: 시작 이미지가 있는가

```python
if has_image:
    return MOTION_PROMPT_I2V.format(camera=…, motion=…, tempo=…, drive=…, audio=…, negative=…)
# 없으면 아래로 — shot·scene·style 을 다시 묘사한다
return MOTION_PROMPT.format(shot_line=…, scene=…, camera=…, motion=…, style=…, …)
```

**이미지가 있으면 장면·스타일을 다시 쓰지 않는다.** 이미지가 이미 그걸 정의했고, 다시
묘사하면 이미지와 싸워서 장면이 어긋난다. 카메라·모션·오디오만 지시한다 (공식 I2V 지침).

> **그래서 `subject_en` 은 I2V 영상 프롬프트에 안 들어간다.** 자유 문장으로 나가는 건
> `motion_en` 하나뿐이다. "영상에서 이렇게 보이게 하고 싶다"는 건 전부 `motion_en` 이거나
> 이미지 단계에서 해결해야 한다. 이걸 모르면 `subject_en` 을 고치며 영상이 안 바뀐다고 한다.

`weather_en` 도 T2V(이미지 없음)일 때만 붙는다 — I2V 는 이미지에 대기가 이미 구워져 있다.

### 카메라가 정해지는 순서

```
① cut["camera"] 가 유효한 프리셋인가?           → 그대로 쓴다
② 아니면 _auto_camera(cut)                     → beat > shot > type 순으로 매핑
③ 체인 컷이면 롱테이크 공식으로 덮어씀           → push → riseorbit → pullup → orbit
   같은 워크가 연달아 나오면 CHAIN_TURN 으로 꺾음
④ 강조(anno_kind 또는 focus_en)가 있고 CAMERA_LOUD 면
   → wide/pov 는 slowpush, 나머지는 still 로 강등        ★
```

**④ 강등이 제일 자주 사람을 놀라게 한다.** 사용자가 `orbit` 을 골라도 강조가 붙은 컷이면
`still` 로 바뀐다. 치수선·화살표는 구조에 고정돼 있어서 카메라가 밀고 들어가면 프레임 밖으로
밀려나고, 그러면 강조가 있으나 마나가 된다 (2026-08-12 실측: 6초 클립에서 화살표가 3초
만에 사라졌다).

`slowpush` 와 `slowslide` 는 `CAMERA_LOUD` 에 없어서 강등을 통과한다 — 강조 컷에서
움직이고 싶을 때 쓰는 유이한 카드다.

**템포도 같이 묶인다.** 카메라를 `slowpush` 로 눌러놓고 템포가 "빠른 리프레임과 핸드헬드
에너지를 환영한다"고 하면 두 지시가 정면으로 싸운다. 그래서 `quiet` 면 `tempo="calm"`,
도착 프레임이 걸렸으면 `tempo="smooth"` 로 강제한다.

### `motion` 에 덧붙는 절들 — 조건이 맞을 때만

순서대로 이어 붙는다. 전부 `motion` 문자열 뒤에 `\n` 으로 붙고, 일부는 `neg` 도 바꾼다.

| 조건 | 붙는 것 | 왜 |
|---|---|---|
| `vanno` 있음 | `video_anno_line(...)` | 주석 애니메이션 |
| 이미지에 글자가 구워짐 | `VIDEO_TEXT_KEEP` + `neg = VIDEO_NEGATIVE_KEEP` | 수치·라벨은 2K 이미지에만 굽고 영상은 **유지만** 시킨다. 720p 에서 새로 그리면 뭉개진다 |
| 홀로그램 컷 | `VIDEO_HOLO_KEEP` | 구워진 홀로그램 유지 |
| `game` | `VIDEO_GAME_PHYS` + `VIDEO_GAME_LOOK` | 게임다움의 절반은 '움직임의 질량' |
| `story3d`·`toy3d` | `VIDEO_GAME_PHYS` + `VIDEO_TONE_LOOK` | 물리는 같고 룩 잠금만 교체 |
| `greycast`·`whitecast` | `VIDEO_GAME_PHYS` + `VIDEO_CAST_LOOK` | **얼굴이 생기는 것까지 막는다** — 얼굴 없음이 정체성 |
| `anime` | `VIDEO_ANIME_LOOK` | 플랫 그림이라 물리는 불필요 |
| 속을 연 컷 (`is_cut_open`) | 잠금 켜짐 → `VIDEO_XSECTION_LOCK` / 꺼짐 → `VIDEO_XSECTION_OPEN` | 아래 참고 |
| 분해뷰 (`is_exploded_cut`) | `VIDEO_EXPLODED_KEEP` | 직선 이동 한 번만. 회전·산개가 대표 실패 |
| 도착 프레임 있음 | 같은 공간 → `VIDEO_LAST_FRAME_ARRIVE` / 다른 공간 → `VIDEO_LAST_FRAME_BRIDGE` | 걸어갈 수 없는 거리를 시키면 모델이 크로스페이드로 때운다 |

**단면 잠금 스위치** (영상 바의 `[단면 잠금]`):
- **켬**(기본) — 이미지에서 이미 갈라져 있으니 영상이 껍질을 휘거나 녹여 **다시 여는** 걸 막는다
- **끔** — "겉면이 걷히며 속이 보이는" 연출을 한 컷 안에서 하려면 이게 걸림돌이라 푼다.
  단 완전 방임은 아니다 — **없던 내부 구조를 지어내는 것**만은 계속 막는다 (대표 실패)

## 자료 소스 탭 — `source_video_prompt`

훨씬 단순하다. 문자열 세 조각이다.

```python
def source_video_prompt(style, cam=""):
    tail = SOURCE_VIDEO_TAIL
    head = ""
    if cam in CAMERA_PRESETS:
        head = f"Camera: {CAMERA_PRESETS[cam]}\n"
        tail = SOURCE_VIDEO_TAIL_FREECAM      # 꼬리의 '카메라 고정' 지시를 뺀다
    return head + "Animate the provided image.\nMotion: " \
           + SOURCE_MOTION.get(norm_style(style), SOURCE_MOTION_DEFAULT) + tail
```

**카메라를 고르면 꼬리가 통째로 갈린다.** 고정 문구가 든 꼬리를 그대로 두고 카메라 워크를
앞에 붙이면 두 지시가 정면으로 싸운다. 그래서 `SOURCE_VIDEO_TAIL` → `..._FREECAM` 으로 바꾼다.

그리고 실제 생성 호출에서도 한 번 더:

```python
camera_fixed=(not cam and style != "tabletop")
```

**`tabletop` 만 예외다.** 미니어처는 시차가 있어야 '작은 모형'으로 읽힌다. 완전히 고정하면
그냥 그림이 된다. 나머지 자료 화면 톤은 기본 고정이다 — 자료 화면은 위에서 평평하게
내려다본 구도라 시점이 조금만 틀어지면 가짜가 되고, 카메라가 움직여 새로 드러난 영역을
모델이 지어내 요소 개수가 바뀐다 (2026-08-13 실측: 미니어처 설원 컷에서 스키어가
5명 → 2명 → 7명이 되고 없던 안개가 생겼다).

### 프롬프트 3단계

이미지 탭과 같은 구조다:
1. 아무것도 안 쓰면 → 톤에 맞는 초안이 자동으로 붙는다
2. 쓰면 → **그게 그대로 나간다**
3. 고정 규칙(카메라·글자 금지)은 초안에 이미 들어 있으므로, 사용자가 지우면 지워진 채로 간다

**보이는 것이 나가는 것**이라는 원칙이다. 화면에 안 보이는 규칙을 몰래 덧붙이지 않는다.

## 만나는 곳 — `_gen_seedance` / `_gen_veo`

여기서만 같은 코드를 탄다. 그래서 **엔진 관련 문제는 양쪽에 동시에 영향**을 준다.

| | Seedance | Veo |
|---|---|---|
| 초 | 2~12 (UI 는 4·5·6·8·10·12 노출) | 4·6·8. **1080p·4k 는 8초만** |
| 카메라 고정 | `--camerafixed` 플래그 | 프롬프트 문구로 |
| 소리 | `generate_audio` (1.5 Pro) | 기본 생성 |
| 체인 | 강함 (도착 프레임 지원) | 약함 |

**엔진마다 쓸 수 있는 초가 다르다.** 베오 표(`VIDEO_SECS_BY_RES`)를 시댄스에 적용하면
10·12초를 골라도 4초로 눌린다 (2026-08-14 실제 버그). 지금은 엔진을 먼저 보고 표를 고른다:

```python
allowed = SEEDANCE_SECONDS if engine == "seedance" else (VIDEO_SECS_BY_RES.get(res) or VIDEO_SECONDS)
if secs not in allowed:
    secs = min(allowed, key=lambda a: abs(a - secs))   # 못 쓰는 값이면 가장 가까운 값으로
```

## 고칠 때 체크리스트

**"영상화를 고쳤다"고 말하기 전에 물어라 — 어느 쪽을?**

- 톤·리빌·체인·강조와 얽힌 것 → **컷 영상화만**. 자료 소스에는 그런 개념이 없다
- 카메라 프리셋 추가 → **양쪽 다** (둘 다 `CAMERA_PRESETS` 를 읽는다)
- 엔진·초·해상도·단가 → **양쪽 다** (`_gen_*` 공유)
- 보관·재생성 → **다르다**. `_archive_prev`(묶음) vs `_archive_one`(단일)
- 판수(N판 미리 뽑기) → **양쪽 다**. 이미지 탭까지 셋

`slowslide` 를 추가했을 때 UI 를 안 건드려도 세 군데 드롭다운에 전부 뜬 이유가 이것이다 —
프론트가 백엔드 `CAMERA_GROUPS` 를 읽어 `camOpts()` 로 그리기 때문이다.
